# Desktop companion extensions

The existing `communication_server.py` `/ws/v1` route remains the single desktop entry point. Restart that service after updating; no additional core server is needed.

The desktop reuses an already running backend. Closing or reopening MyAI does not reload that backend's imported Python modules. After a backend update, restart the `communication_server.py` process itself; a successful `/health` response establishes availability, not whether a previously running process has loaded new source code.

Generated document delivery: websocket `write_file` outputs (TXT/Markdown/CSV/TSV/JSON/XML/HTML/PDF/Office/images/ZIP, at most 64 MiB) are registered by conversation and task when newly created, already owned, or explicitly named as a write/save destination in the current user goal. This also handles rewriting a previously unregistered translation. Merely mentioning an input file does not adopt it; retained program resources keep their retention policy. Use a workspace-relative destination, independently of the input file directory. `chat.end.payload.files` carries verified `{id,name,size,sha256}` entries; the independent judge also receives these filesystem-verified facts and the workspace delivery policy. File presence alone does not waive content verification or unrelated tool failures. A refused duplicate write is recovered only when the same successful tool input and filesystem-verified output still match.

Clients send `file.get` with `{file_id,offset}`; transient `file.chunk` replies contain the same metadata plus `{offset,data,eof}`, where `data` is base64 and chunks are at most 256 KiB. Responses use the request `ref`; errors use `file_unavailable`. Downloads require the same authenticated conversation and an active session, accept no arbitrary filesystem path, and reject replacement objects, links and hard links. Clients must verify the complete SHA-256 before publishing a local copy. Session deletion previews include `outputs`; confirmed native cleanup removes the frozen output objects and skips files manually deleted before or after preview. Downloaded copies outside the managed source location remain independent.

`hello.payload.conversation_id` is optional (empty preserves legacy sessions). A nonempty ID must match `[A-Za-z0-9_-]{1,64}`. Runtime, task/approval scope, reliable outbox and input deduplication use the conversation scope. Each physical device has at most 50 in-memory sessions; inactive sessions may be evicted. Durable event replay does not guarantee restoration of model context after eviction/restart.

`welcome.features` advertises `conversation_sessions`, `attachments` limits and `desktop_tools`. `welcome.connection_id` binds desktop tool calls to this connection, so reliable replay of a previous connection's tool request must never execute an effect.

`chat.send.payload.attachments` is a list of `{filename, content_type, data_base64}`. Limits: 4 files, 1 MiB each, 2 MiB total, 4 MiB JSON envelope. Filenames must be basenames; image MIME and actual PNG/JPEG/WebP/GIF bytes/dimensions are validated. Bytes become `InboundAttachment` objects passed to the existing runtime/media parser, including suspended user answers. Transport slash commands reject attachments. The input deduplication fingerprint includes attachment names, types and byte hashes. Attachments are not copied to an extra persistent file store by this transport.

Large text uploads are retained in conversation-owned temporary `uploaded-text-*` directories. The message carries a hash, complete character count and a workspace reference instead of embedding or truncating the source. `read_file(path, offset, limit)` supports Unicode character ranges (at most 4096 characters per ranged read), preserving source newline offsets. Short text remains inline for ordinary tasks. Sources are covered by the existing session deletion preview and native cleanup.

Per-turn cleanup is advertised by `welcome.features.workspace_lifecycle.turn_cleanup=true`. Clients send `turn.delete` with `{request_id}`; the reliable `turn.delete.result` uses the control request's `ref` and contains the target `request_id` and `state`. Only `state=deleted` authorizes removing the local turn, atomically with the reliable event cursor before ACK. `turn.delete.status` queries the same target without repeating deletion; `not_started` permits an explicit retry. Cleanup removes that authenticated conversation/task's registered output objects and unshared temporary upload sources, skipping missing objects. Original user files, independent downloaded copies, other turns, shared sources and retained resources remain. Active workers and unresolved effects block cleanup. A durable frozen plan supports partial-failure retries; a completed retry cannot delete a later file reusing the same name. Deleted task IDs are fenced against late writes. Older source references are recovered from scoped task checkpoints. Restart both backend and desktop to load this protocol and its UI behavior.

Desktop requests to translate complete text attachments into Traditional Chinese use a bounded translation workflow in the SQLite Agent runner. It checkpoints completed source ranges, splits fragments again if the provider reports an output length limit or the context admission rejects the fragment, and writes each `_zh.txt` output after all its source ranges have been translated. Provider errors can resume saved progress without repeating completed ranges. Source hashes are rechecked; incomplete/empty model responses are rejected. Existing model hooks, write permissions, task budgets, cancellation and acceptance checks still apply. Native Temporal step execution continues to use its existing tool workflow with the staged references and ranged reads. The task request/token/deadline limits are not automatically increased: oversized translations report the required number of requests rather than silently dropping text. Restart PythonAI after updating; this upload fix does not require a desktop binary change.

Clients may opt into `desktop.system_info`, `desktop.open_url`, `desktop.open_path`, `desktop.clipboard_write` capabilities. The model tool `desktop_tool(action, arguments)` and human `/desktop <action> <value>` command share a per-turn bridge. viewer is limited to system_info; operator cannot write the clipboard; admin can use all four. Other transports return an unavailable result and never execute local effects on the server.

Server sends reliable `tool.call` with `{action, arguments, timeout_ms:60000, connection_id}` and `ref` equal to the chat request. Client replies `tool.result` with the call ID in `ref` and `{ok:bool,data,error}`. Matching is per session and current WebSocket connection, with a 16 KiB result limit. The client validates its own URL/path allowlist and requires local human approval for effects. Timeout, chat cancellation, disconnection and replacement cancel the waiter; uncertain effects must not be retried automatically.

Tests: `tests/test_companion_features.py`, existing WS tests, and MyAI's controlled real ASGI/runtime integration suite. None require an external model provider.

`welcome.features.approval_auto_resume=true` advertises optional human approval waits. Clients opting into `hello.capabilities=["approval.auto_resume", ...]` receive reliable `approval.required` with `auto_resume:true` while the original tool/task remains paused. `approval.decide` persists the admin's scoped decision; `approval.result.auto_resume` indicates continuation of that live operation, not completed effects. The worker consumes the original single-use grant and rechecks role, paths, delivery snapshot and task budget before executing. It does not resend `chat.send` or rerun preceding tools. Denial, expiry, cancellation and disconnection do not execute the operation; cancelled/expired waits send reliable `approval.cancelled`. Backend restart does not automatically replay an uncertain tool. Clients without the capability and all other transports retain the existing approval/retry behavior.

Vision context budgeting counts the actual text/schema bytes and reserves image tokens separately; a Base64 data URL is transport data, not text tokens. The complete URL is retained for the provider. `AGENT_MODEL_IMAGE_TOKENS` defaults to 8192 per image; a routed model's `AGENT_MODEL_CAPABILITIES` profile can override this with a positive integer `image_input_tokens`. This is an adjustable reservation for arbitrary OpenAI-compatible providers, not an exact model tokenizer. Calibrate it to the deployed model and image detail/resolution. Successful responses and normally completed streams settle token reservations to valid provider-reported usage, including upward adjustments; failed, interrupted or unreported calls retain their reservations. Request counts and conservative cost charges are not refunded. Multiple images still count separately, and real text/schema/protected context overflow still fails before a model call. See [OpenAI Docs image tokenization](https://developers.openai.com/api/docs/guides/images-vision#calculating-costs) for model-specific patch/tile rules.

MyAI suite 64 passed, including a valid roughly 200 KiB PNG sent through the real ASGI/runtime/budget path to a controlled model endpoint, with a matching byte hash. External provider recognition quality is not covered by that fixture; restart the deployed server to load this fix before testing a real provider.
